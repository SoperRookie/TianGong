# 说明

本清单按代码现状逐项统计，不含规划中或未实现的功能。统计来源：`app/api/routes.py` 全部路由、`app/web/index.html` 侧栏页面、`app/prompts.py` Prompt 注册表、`app/config.py` 配置项、`docs/业务流程与节点逻辑.md` 各节点逻辑、各版本发布说明。「入口」列给页面位置或接口路径，便于对照验证。与 v2.1.4 清单（2026-10-15）相比，本版补入 v2.1.4 后半程（10-16 ～ 10-28）与 v2.2.0 的全部功能。

## 业务主线

```
需求录入（原文 / 文件 / 链接；同名附件先查重）
  → 附件解析（文档 · 图片理解 · 压缩包 · Axure 原型包带坐标）→ 内容体检 / 识图告警
  → 需求提取（按文件 › 页面分层摘录 → 逐条核验 → 底稿双向核验 + 补漏 → 整稿交叉核对
               → 逐条审核 / 底稿核对 → 版本存档 → 章节归端 → 三端汇总）
  → AI 需求分析（分片 → 11 项 → 原文核验 → 独立复核 → 推荐答案）→ 人工拍板 → 确认沉淀 / 进评测集
  → 发起测试设计（design_brief 拼上下文，确认结论回对应分片）
  → 需求拆解（标题大纲 → 端到端场景 → 分片拆点 → 经验延伸 → 盲区复核 → 按章节查漏
               → 模块级组合延伸 → 语义查重 → 独立评审 → 测试点归端）
  → 测试点审核（按端分列表；通过 / 驳回 / AI 修正 / 盲区处置 / 重复对处置）
  → 用例生成（按端单独确认；LangGraph：生成 → 独立评审 → 定点修正 ≤ 3 轮；只带本模块章节）
  → 用例评审（按端分页签；人工 / AI 修改提案 / 语义查重裁判 / 多轮修订 / 离线终稿以终稿为准）
  → 用例中心（正式用例）→ 测试计划（AI 挑选、快照）→ 执行轮次（AI 归因 / 缺陷单 / 测试报告）→ 报表
  → 导出（测试点 / 用例的 xlsx · csv · xmind，整份或按端）
      ↘ 审核通过的测试点 / 用例 / 终稿 / 已确认分析 → 知识库（增量向量化）→ 项目画像 → 注入全链路
```

# 三、需求中心

## 3.1 需求录入与附件解析

| 编号 | 功能 | 当前实现 | 入口 |
|----|------------|--------------------------------------------|--------------------|
| 3.1.1 | 需求实体 | 标题、原文、附件、链接、补充说明、版本、模块、状态、创建人；原文创建后不可改（只能改标题 / 补充 / 版本 / 模块 / 状态）；来源类型 manual / file / link / mixed / migrated | 需求列表页；`GET/POST/PUT/DELETE /requirements[/{id}]` |
| 3.1.2 | 多种录入方式 | 文字粘贴、多文件上传（累加式选择）、正文或 `urls` 里的链接（最多 10 条，只抓公网 http(s)），三者可混合 | 新建需求 |
| 3.1.3 | 附件后台解析 | 文件落盘立即返回，PDF 提取与图片理解在后台串行；每个附件记录 parsing / parsed / error / 字数与识图统计 `vision`（有识图失败的显示「部分解析」并告警「k/n 张图片识图失败」）；服务重启时未完成的标失败提示重解；解析中禁止 AI 分析与发起设计（409） | 需求详情 → 附件 |
| 3.1.4 | 追加 / 重新解析 / 下载 / 删除附件 | 任何已存附件都可重新解析（不限于失败的）；链接附件本地文件还在时只重解不重抓；删除附件连文件一起删（解析中 / 提取中 409），指纹变化让整理稿与分析过期；解析全文可按文档格式整篇查看 | `POST /requirements/{id}/attachments`、`.../{att_id}/reparse`、`GET/DELETE .../{att_id}`、`GET .../{att_id}/text` |
| 3.1.5 | 同名附件查重 | 新建需求选了文件时先查同项目在用需求里带同名附件的（按创建时间倒序，带状态 / 任务数 / 待确认事项数 / 是否有整理稿）；有命中弹窗问「作为新版本替换到 X」（删旧附件 + 追加新文件 + 补充说明并入，解析完自动重提、人工决定沿用）还是「仍新建」 | 新建需求；`GET /requirements/same-files` |
| 3.1.6 | 可读取格式 | Word / Excel / PowerPoint 全系（含 doc / xls / ppt 老版、宏与模板格式）、WPS、OpenDocument、RTF、PDF（含扫描版，无文本层的页整页栅格化送图片理解，≤ 300 页）、Markdown / TXT / JSON / XML / YAML / 日志等文本、网页、图片 16 种后缀（走 Vision，svg / emf / wmf 经 LibreOffice 栅格化）、压缩包 zip / tar / gz / bz2 / xz / 7z / rar（递归，嵌套 2 层，脚本样式资源只计数不解析，zip 内无 UTF-8 标志的中文文件名按 UTF-8 / GBK 还原）、Axure 原型导出包（见 3.1.7）、邮件 eml / msg（正文与附件）；视频、字体等保留下载不解析 | `app/parsers/` |
| 3.1.7 | Axure 原型包深度解析 | 按站点地图顺序（含 Axure 9/10 混淆格式的 document.js）逐页提取；每个文字控件带编号 `[u1125]` 与坐标，沿父链累加坐标后按 round(y/4px) 分行、行内按 x 排序还原阅读顺序，下拉选项 / 输入值单独成行，隐藏控件照提并标记；页面标题带站点地图文件夹路径；表格同一行单元格并成一行、跨行合并格单独一行；流程图按线段几何定起止、分支标签就近归属，整张还原成「A —是→ B」边列表；相距 ≥ 1000px 的控件群算独立区域（疑似遗留草稿）；几张示例小图并排时按说明划单元格、文案归到各自说明后；整页字符多重集自校验（有文字不在控件里的页报缺字）；整幅设计稿送图片理解 ≤ 30 张，svg 切片不送 | `app/parsers/axure.py` |
| 3.1.8 | 文档内嵌图理解 | Word 段落与表格单元格内图片、PDF 图片（跨页去重）、PPT 页内图片按位置提取送图片理解；装饰图（短边 < 100px 或 < 3KB）跳过；4 路并发，单图失败只替换成失败说明并计入 `vision.failed` | `app/parsers/enrich.py` |
| 3.1.9 | 大图切块理解 | 最长边 > 2000px 切块（步长 1880、重叠 120），每块注明块序与行列，结果按序拼接；块数 > 16 才整体缩小；单块 ≤ 5MB | `app/parsers/image.py` |
| 3.1.10 | Excel 需求智能判型 | 按工作表自动判「数据型」（逐行输出 列名：值）或「文档型」（按行拼接），嵌入图片按锚点行插占位 | `app/parsers/table.py` |
| 3.1.11 | 老格式转换 | doc / xls / ppt / wps / rtf 等经 LibreOffice 转新格式后解析（180 秒超时，没装给明确提示；Docker 镜像已内置） | `app/parsers/convert.py` |

| 3.1.15 | 需求列表筛选与分页 | 状态 / 来源类型 / 创建人 / 业务线 / 关键词（扩展到补充说明与附件），统一分页 | 需求列表页 |

## 3.2 需求提取（分析前置）

| 编号 | 功能 | 当前实现 | 入口 |
|----|------------|--------------------------------------------|--------------------|
| 3.2.1 | 分层提取 | 原文 + 全部已解析附件 / 链接文本 → 按「文件 › 页面 / 章节」切成单元（同文件小页面打包到 20000 字，超限页面才再切；图片理解块内的标题不算章节，文件自己的标题不进路径），每次调用带所含页面路径 → 模型先列页面区块清单再按区块逐字摘录（功能、规则、数值边界、状态、权限、流程、异常与文案、外部依赖、配置项、字段清单与枚举值、带规则的示例、设计约束与入口位置示例、流程图分支半句），材料是什么形式就按什么形式成条，只剔除导航 / 版权 / 框架文字 / 脚本样式 / 纯样例数据 / 只讲外观的行 → 模块「页面-区块」合并、条目逐字去重合并来源；区块名必须来自材料，对不上的换成区块开头的原文小标题 | `app/agents/extraction.py`、Prompt `requirement_extract` |
| 3.2.2 | 原文逐项对照 | 每条程序对照材料逐字核验：含数字 / 运算符 / 百分号的整句严格命中（「≤0」不能靠「>0」过关），其余分段 ≥ 70%；没找到的标 ⚠，短条目按子串判；每条有稳定 id | `verify_modules` |
| 3.2.3 | 底稿双向核验与自动补漏 | 材料里产品写的每一行是一个底稿单元（Axure 行用控件编号、其余「文件序号-行号」，同句多处只记一个并记次数 / 页面；图中文字单独一栏不送模型不兜底）；核算每句去向：收录（整行子串或切段命中 ≥ 90%）/ 排除（模型 / 程序 / 人工，程序只判纯样例数据）/ 待处理；待处理全部带编号送补漏模型判「补进 / 跳过」（每批 ≤ 15000 字并行，最多 2 轮，只认原句），轮次用完仍未判的按原句收进「页面-待归类」标〔兜底〕；模型排除里带数字 / 条件词或理由含「片段」的标「需复核」；需求句覆盖率入 meta | `app/agents/ledger.py`、Prompt `requirement_extract_gap` |
| 3.2.4 | 整稿交叉核对 | 全部条目带 id 一次送模型（≤ 150000 字），只找跨页面 / 跨文档矛盾（追加到条目疑点）与疑似遗留草稿（整块标〔疑似遗留草稿〕）；模型出错只跳过 | `TIANGONG_REQUIREMENT_EXTRACT_CROSSCHECK`、Prompt `requirement_extract_crosscheck` |
| 3.2.5 | 层级化整理稿与文档式预览 | 按「文件夹 › 页面 › 区块 › 条目」三级编号生成整理稿（表格行还原成表、原文小标题作加粗子标题、示例图说明与文案并成一行、连续流程行画成分支树）；文头含标题 / 来源 / 提取原则 / 校验，末尾疑点 / 不一致清单与已剔除说明；「预览」页签按文档格式渲染，左侧目录吸顶可点、滚动高亮 | 需求详情 → 需求提取 → 预览 |
| 3.2.6 | 自动触发 | 附件解析完成即后台提取一次；附件疑似非需求文本或识图失败告警时跳过；纯手填原文无附件的需求不提取 | 自动 |

# 十五、有意保留的设计边界

- 单进程架构：用户、项目、任务为进程内内存态加数据库回写，不支持多实例部署。
- 未确认或已过期的分析仍会进测试设计上下文；确认是沉淀知识库的门槛，不是设计的门槛。只有带复核质疑未处理的条目被跳过。
- 附件追加 / 重新解析 / 删除不会清掉已有分析，只提示重新分析；整理稿过期则在分析与设计前自动重提。
- 需求提取只摘录不改写；模型改写的条目保留并标 ⚠ 交人核对，不自动删除；轮次用完仍没判定的句子宁可兜底收进交人排除，不静默丢。整理稿不单独沉淀知识库。
- 端只是归类维度：改端不改需求与测试点文本；提取时的章节归端只影响之后发起的任务，已拆完的任务按自己的归端走；端到端场景点只验跨端一致性，不替代各端的明文测试点。
- 拆解与延伸分成两次调用：拆解只认原文宁多勿漏，延伸 / 组合 / 端到端只补需求之外、条数受限、条条有依据。
- 需求变更 `apply` 只改任务上下文里的需求文本，不回写需求中心原文。
- 批量确认不触发自动加评测样本。
- Axure 导出包里的 svg 切片一律不送图片理解。
- 分片之间不重叠，跨片靠全文大纲衔接；确认结论与人工补充按模块回到对应片。
- 执行失败只记录事实与证据，AI 归因与缺陷单是草稿，采纳才改分类；不进入缺陷流程。
- 测试报告的数字由程序统计、结论由程序按数据校正，模型只写文字。
- 自我学习体系为「提炼规则 → 管理员确认 → 注入生成」，不做离线自动调优。
