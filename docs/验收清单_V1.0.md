# 天工 V1.0 验收清单

对应排期「验收周（11-02 ~ 11-06）」四项：存量数据正式迁移、试点项目全流程走查、第 23 章 25 条核心规则逐条验收、缺陷修复缓冲。
本清单三部分均可执行：迁移有脚本与报告接口，规则有自动化验收测试（`tests/test_acceptance_rules.py`），走查有逐步勾选表。

## 一、存量数据正式迁移

迁移逻辑在应用启动时自动、幂等执行（`app/main.py`）：

| 步骤 | 内容 | 实现 |
|---|---|---|
| 1 | 历史执行轮次 → 计划执行（每个带轮次的任务自动建一个计划，用例全量快照，轮次结果按 uid 对应到快照） | `app/plans.py: migrate_task_executions` |
| 2 | 历史任务 → 需求实体（一个任务 = 一条需求，`source_type=migrated`，回填 `requirement_id`） | `app/requirements.py: migrate_tasks` |
| 3 | 「未指定项目」的遗留任务：管理员逐个归属项目，归属后自动完成第 2 步，迁移期生成的计划一并改挂 | `PUT /api/v1/tasks/{id}/project`；页面：项目管理 →（未指定）→ 概览 |
| 4 | 迁移报告：任务归属 / 需求实体化 / 执行迁移完成度与待处理清单 | `GET /api/v1/admin/migration`；`scripts/migrate_prod.sh --check <token>` |

正式执行步骤（生产）：

1. `TIANGONG_DB_URL=... scripts/migrate_prod.sh` 全量备份到 `backups/`（mysqldump，附回滚命令）。
2. 启动服务，启动日志输出「M4 执行迁移 N 个任务」「M2 需求迁移 N 个任务」。
3. 管理员登录，`scripts/migrate_prod.sh --check <token>` 或打开 项目管理 →（未指定），把未归属的遗留任务逐个「归属项目」。
4. 报告显示「已完成」即迁移闭合；否则按清单处理后复查。

自动化：`tests/test_migration.py`（归属→需求实体化→报告闭合；迁移计划随任务改挂）。

执行记录（2026-09-08，本地库）：备份 `backups/tiangong-20260908-165004.sql.gz`；81 个遗留任务中，「AI测试用例生成工具核心需求设计」1 个归入 天工，走地德州相关 5 个归入 走地德州，其余 74 个联调小任务归入新建的 历史归档；每个任务已自动建为一条 `migrated` 需求。剩 1 个「登录功能（PC+移动端）」任务无对应项目，待确认后归属。
