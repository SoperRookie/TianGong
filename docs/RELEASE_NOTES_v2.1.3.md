## 需求提取（分析前置）

**为什么**：原型导出包、整页截图的图片理解结果、多份文档拼在一起时，需求事实散落在导航 / 页眉页脚 / 框架文字 / 样式脚本 / 重复页面之间。直接送去分析，模型要在几万字噪音里找规则，分片后同一条规则还会在不同片各写一遍，最后体现为分析项和测试点忽多忽少。

**做什么**：用户上传需求、附件解析完成后，先对**原文与全部附件**做一次提取：

- 逐字摘录与需求有关的句子（功能、规则、数值边界、状态流转、角色权限、流程、异常与文案、外部依赖、配置项），保留原文措辞、数值、单位、方向，不改写不概括不补充。
- 剔除导航、版权、重复框架文字、脚本样式、图片理解的客套话与纯外观描述；同一事实多处出现只留一条并标全部来源。
- 按「大模块-子模块」归整成整理稿；每条程序对照材料逐字核验（与分析的 quote 核验同一套规则），没逐字找到的加 ⚠ 交人核对；末尾列出剔除了哪些类型的内容。
- 长材料按 20000 字分片并行提取后按模块合并。

**怎么用**：

- 自动：附件解析完成即后台提取一次（附件疑似非需求文本时跳过）。AI 分析与发起测试设计前，没有整理稿或整理稿已过期（附件有追加 / 重新解析）会先提取。纯手填原文、没有附件的需求不提取，直接用原文。
- 手动：需求详情新增「需求提取」页签：提取 / 重新提取（可选模型）、查看整理稿（⚠ 条目高亮）、直接修改保存、删除整理稿退回原始材料。
- 下游：AI 需求分析、发起测试设计（含多需求合并）以整理稿替代原文与附件文本，人工补充与待确认结论照常追加；分析页标明本次分析输入是整理稿还是原始材料。重新提取、人工修改或删除整理稿后，已有分析标「基于旧输入」。
- 配置 `TIANGONG_REQUIREMENT_EXTRACT`（默认 true）：关掉则不自动提取、分析前也不提取，只保留手动入口。
- Prompt 管理新增「需求提取（分析前置）」可版本化调整；操作日志记录提取 / 修改 / 删除整理稿。

## 升级后

- 已有需求不会自动补整理稿，下次点 AI 分析或发起测试设计时会先提取一次（多一次模型调用）。
