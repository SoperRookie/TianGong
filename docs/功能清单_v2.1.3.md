## 业务主线

```
需求录入（原文 / 文件 / 链接）
  → 附件解析（文档 · 图片理解 · 压缩包 · Axure 原型包）→ 内容体检
  → 需求提取（全部材料逐字摘录 → 按模块归整 → 逐条核验 → 整理稿）        ← v2.1.3 新增
  → AI 需求分析（分片 → 11 项 → 原文核验 → 独立复核）→ 人工拍板 → 确认沉淀 / 进评测集
  → 发起测试设计（design_brief 拼上下文）
  → 需求拆解（大纲 → 分片拆点 → 盲区复核 → 覆盖查漏 → 语义查重）
  → 测试点审核（通过 / 驳回 / AI 修正 / 盲区处置 / 重复对处置）
  → 用例生成（LangGraph：生成 → 独立评审 → 定点修正 ≤ 3 轮）
  → 用例评审（人工 / AI 修改提案 / 多轮修订 / 离线终稿）
  → 用例中心（正式用例）→ 测试计划（快照）→ 执行轮次 → 报表
      ↘ 审核通过的测试点 / 用例 / 终稿 / 已确认分析 → 知识库 → 项目画像 → 注入全链路
```

| 3.1.4 | 追加附件 / 重新解析 / 下载 | 任何已存附件都可重新解析（不限于失败的）；链接附件本地文件还在时只重解不重抓 | `POST /requirements/{id}/attachments`、`.../{att_id}/reparse`、`GET .../{att_id}` |

| 3.1.6 | 文档内嵌图理解 | Word 段落与表格单元格内图片、PDF 图片（跨页去重）、PPT 页内图片按位置提取送图片理解；装饰图（短边 < 100px 或 < 3KB）跳过；4 路并发，单图失败只替换成失败说明 | `app/parsers/enrich.py` |
| 3.1.7 | 大图切块理解 | 最长边 > 2000px 切块（步长 1880、重叠 120），每块注明块序与行列，结果按序拼接；块数 > 16 才整体缩小；单块 ≤ 5MB | `app/parsers/image.py` |
| 3.1.8 | Excel 需求智能判型 | 按工作表自动判「数据型」（逐行输出 列名：值）或「文档型」（按行拼接），嵌入图片按锚点行插占位 | `app/parsers/table.py` |
| 3.1.9 | 老格式转换 | doc / xls / ppt / wps / rtf 等经 LibreOffice 转新格式后解析（180 秒超时，没装给明确提示；Docker 镜像已内置） | `app/parsers/convert.py` |

## 3.3 AI 需求分析闭环

| 3.3.8 | 批量确认 | 按项目或全部（管理员）把已分析未确认（含旧版本）的一次确认并后台沉淀；预览按未分析 / 已确认 / 复核质疑未处理 / 待确认四组计数 | 需求列表 → 批量确认分析结果；`GET/POST /requirements/analysis/batch-confirm` |

| 3.3.12 | 追溯与覆盖 | 需求详情展示派生任务、测试点、用例、计划、执行的追溯与覆盖识别 | 需求详情 |

# 四、测试设计任务（需求拆解）

| 编号 | 功能 | 当前实现 | 入口 |
|----|------------|--------------------------------------------|--------------------|
| 4.1 | 创建任务 | 上传 / 粘贴需求直接建任务，或从需求发起；可选「先确认测试点」、模型、评审模型、模板、知识空间（借用其他项目须有其知识查看权） | 任务看板 → 新建；`POST /tasks` |
| 4.2 | 异步执行与并发 | 进程内异步执行，同时执行数 `TIANGONG_TASK_MAX_CONCURRENCY`（默认 2），超出排队；排队中与执行中可取消；页面轮询进度 | `POST /tasks/{id}/cancel`、`GET /tasks` |
| 4.3 | 长需求分片拆解 | 20000 字分片，先出全文模块大纲再逐片拆解（模块命名一致、本片没涉及的不生成）；空片跳过 | 自动 |

# 十五、有意保留的设计边界

- 单进程架构：用户、项目、任务为进程内内存态加数据库回写，不支持多实例部署。
- 未确认或已过期的分析仍会进测试设计上下文；确认是沉淀知识库的门槛，不是设计的门槛。只有带复核质疑未处理的条目被跳过。
- 附件追加 / 重新解析 / 删除不会清掉已有分析，只提示重新分析；整理稿过期则在分析与设计前自动重提。
- 需求提取只摘录不改写；模型改写的条目保留并标 ⚠ 交人核对，不自动删除。整理稿不单独沉淀知识库。
- 需求变更 `apply` 只改任务上下文里的需求文本，不回写需求中心原文。
- 批量确认不触发自动加评测样本。
- Axure 导出包里的 svg 切片一律不送图片理解。
- 分片之间不重叠，跨片靠全文大纲衔接。
- 执行失败只记录事实与证据，不进入缺陷流程。
- 自我学习体系为「提炼规则 → 管理员确认 → 注入生成」，不做离线自动调优。
