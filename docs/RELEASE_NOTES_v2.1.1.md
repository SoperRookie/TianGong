# 天工 v2.1.1 发布说明

- 版本：v2.1.1
- 发布日期：2026-10-14
- 标签：`v2.1.1`（dev 分支）
- 性质：修复版本，解决压缩包内文档图片理解结果丢失与大图识别失真两个影响需求覆盖面的问题；升级步骤与 v2.1.0 相同

## 修复

### 压缩包内文档的图片理解结果丢失

压缩包里既有独立图片又有带插图的 Word / PDF / PPT 时，合并子文档的图片占位要重新编号。早先是逐张边改边替：子文档第 1 张改成 `[[图片:5]]` 后，处理第 5 张时又把它改成 `[[图片:9]]`……连锁覆盖的结果是前面几张图的占位全部丢失，只剩最后几张各重复多次；这些图的 Vision 理解都做了（照常计费），但回填时找不到占位，整段内容直接消失。

生产上「连赢活动前端+后台」需求的 `连赢活动后台需求.docx` 12 张页面截图只留下 4 张（各重复 3 次），活动列表 / 派奖查询 / 连赢活动统计 / 活动设置管理 / 会员流水 / 日榜排名 等 8 页全部丢失，拆解出的后台测试点因此偏少。现改为先算好全部映射再一次性替换。

受影响的存量需求：附件解析文本里同一个「文档内图片理解」编号出现多次即为中招，在需求详情附件列表点「重新解析」即可恢复，之后需重新分析、重新发起设计。

### 大图切块理解

整页原型截图 / 长截图往往几千到上万像素，早先整体缩到最长边 2000 像素再送模型，文字糊成一片，模型只能概括大意（输出标题常是「需求摘录」），字段、文案、数值大量丢失。现按 2000 像素切成带 120 像素重叠的块逐块理解（每块提示词注明块序与行列，只描述本块可见内容），结果按顺序拼接；块数超过 16 才整体缩小。独立图片与文档内嵌图都走这条路径。

### 文档内嵌图改用完整图片理解提示词

Word / PDF / PPT 内嵌图早先用一句「简洁输出」的内置提示词，整页原型截图被概括成几百字摘要。现与独立图片同用 Prompt 管理里的「图片理解」（界面元素清单 / 交互逻辑 / 业务规则 / 图中文字原文完整转录），前面只加一句所处上下文；该提示词可在 Prompt 管理页版本化调整。

### 需求分析闭环补漏

- 发起测试设计时，独立复核标了理解错 / 无依据且人还没处理的条目不再进入拆解上下文（之前会以「已经人工过目」的名义送给拆解 Agent）。
- 批量确认分析结果与单条确认同一规则：复核质疑未处理的需求跳过，预览里单列条数。
- 需求分析评测运行时带项目画像，与线上分析条件一致。

### 其他

- 新增 `docs/业务流程与节点逻辑.md`：按当前代码逐节点梳理的业务流程、阈值与已知缺口。

- `app.agents` 包导出改为按需加载，消除 `app.prompts ↔ app.agents.service` 的循环导入（单独运行解析器测试时触发）。

## 升级后建议

1. 对 Axure 原型导出包（v2.0.0 起识别）与带插图文档的存量需求点「重新解析」，解析完核对字符数与图片块数再重新分析。
2. 原型截图尽量按页面单张上传，每张几千像素高的长图现在可以识别，但多页拼成一张超大图仍会被缩小。
