# 天工 v1.0.0 发布说明

- 版本：v1.0.0（首个正式版本）
- 发布日期：2026-09-16
- 标签：`v1.0.0`（对应 dev 提交 9c4cf85，test 分支同内容）
- 适用范围：内网部署，MySQL 8 + Python 3.12

## 概述

天工是面向测试团队的 AI 测试用例管理平台。围绕「需求 → 测试点 → 用例 → 计划 → 执行」一条主线，由 AI 完成需求分析、测试点拆解、用例生成与独立评审，人工负责确认与审核，全过程留痕可追溯。v1.0.0 覆盖完整需求文档 V1.0 的全部里程碑（M1–M5、M4b），第 23 章 25 条核心业务规则已逐条自动化验收，试点项目全流程走查完成。

## 功能一览

### 项目与权限

- 项目实体：编码、负责人、版本、模块树（层级、排序、逻辑删除，被用例引用不可物理删除）、归档只读、收藏与最近访问。
- 系统级角色（管理员 / 成员）与项目级角色（项目管理员 / 测试负责人 / 测试人员 / 只读）分离，同一用户在不同项目可拥有不同角色。
- 所有业务接口按「所属项目 + 动作」校验，非成员对项目数据一律不可见，杜绝跨项目访问。
- 用户资料、启用禁用（禁用即会话失效）、最后登录时间与 IP、管理员重置密码与角色。

### 需求中心

- 需求实体化：文本录入或多格式附件（PDF / Word / 图片 / 文本），原文永久保留，AI 结果与人工补充独立存储，逻辑删除可恢复。
- 附件后台解析，逐文件记录失败原因，可重新解析；解析中禁止发起 AI 分析与测试设计。
- AI 需求分析 11 项结构化输出（功能点、业务规则、前置条件、正常 / 异常流程、边界条件、外部依赖、待确认事项等）。
- 待确认事项未全部回答不能进入测试设计。
- 需求状态流：草稿 → 已分析 / 待确认 → 已确认 → 设计中 → 已完成 / 归档。
- 重复导入治理：需求「合并到…」把任务、附件、待确认事项并入目标需求，来源进回收站并记录去向。

### AI 测试设计与评审

- 多 Agent 流水线：测试点拆解 → 用例生成（按模块并行）→ 独立评审，不合格项定点打回，最多 3 轮。
- 测试点覆盖矩阵与自动查漏、查重。
- 测试点与用例默认待审，评审通过后才成为正式内容；只有通过的测试点进入用例生成，只有通过的用例可加入计划。
- 结构化驳回：类型多选、原因必填、修改要求与范围；用例支持字段级与步骤级定位。
- AI 定向修改只动被驳回或明确选中的内容，产出提案并展示差异，人工确认后才落地并重新进入评审；已通过内容锁定，AI 不得自动修改。
- 版本链：AI 原始 → 人工修改 → AI 二次修改 → 终稿，任意版本可恢复且不覆盖历史。
- 乐观锁：多人同时编辑冲突拦截，批量维护逐行反馈冲突。
- 测试点审核与用例审核均提供表格与脑图双视图，脑图可选中节点直接通过 / 驳回 / 修改。
- 导出 XMind、Excel、CSV。

### 用例库与人工维护

- 全库用例跨项目、跨任务聚合浏览，按项目 / 模块 / 优先级 / 生命周期 / 关键词筛选，只读脑图视图。
- 人工用例集：新增、复制用例（草稿 → 提交评审）。
- Excel / CSV / XMind 导入五步校验：上传 → 解析 → 预览 → 逐行校验 → 确认，错误行不会静默导入，可只导入无错误行，提供模板下载。
- 批量维护：提交评审、改优先级、改模块、加标签、加入计划、删除入回收站。
- 回收站：核心数据默认逻辑删除，可恢复；仅管理员可永久删除。

### 测试计划与执行

- 计划实体：名称、负责人、周期、状态；只能加入已通过用例，加入即生成带版本号的快照，正式用例后续修改不影响历史计划。
- 分配：按用例或按模块分配执行人（候选为项目成员），并发分配冲突拦截，改派留痕。
- 执行：每轮独立保存，同轮重录保留历史；结果为通过 / 失败 / 阻塞 / 跳过，失败必填分类与说明；附件可挂整轮或具体用例。
- 失败只记录事实与证据，不进入缺陷流程；用例问题类失败自动进入学习语料。
- 已分配用例仅本人可执行，负责人可代执行并留痕。

### AI 中心、统计与审计

- 全部 17 个 Prompt 版本化管理：草稿、激活、回滚、归档，占位符校验。
- AI 调用日志记录模型、Prompt 版本、输入、输出与发起人，可回溯到任务；失败任务可重试，部分成功明示。
- 报表：产出、质量、审核效率、采纳率、用例执行情况、AI 质量五指标，按项目与时间窗口过滤。
- 操作日志：全部写接口自动采集（操作人、IP、UA、项目、对象、耗时），登录成功 / 失败与登出入安全日志，默认保留 180 天。

### 知识库、记忆与依赖关系

- 知识库三层：公共 / 项目 / 模块。公共层仅系统管理员维护并跨项目可用，项目知识严格隔离。
- 向量 + 关键词混合检索，Embedding 采用 OpenAI text-embedding-3-large。
- 长期记忆：用户偏好与项目记忆跨会话保留，常用模板 / 模型与重复修订要求自动沉淀。
- 依赖关系：需求功能依赖与用例依赖链路，AI 识别为草稿、人工确认后生效，前置关系禁止成环。

### 工作台、搜索与追溯

- 我的工作台：我的项目、待评审、待修改、待执行、待确认需求、我的 AI 任务、最近操作。
- 全局搜索：跨需求、任务、测试点、用例、计划、知识。
- 覆盖追溯：需求 → 测试点 → 用例 → 计划 → 执行正反向可点。
- 项目概览：最近任务、需求状态分布、进行中计划、成员数与快捷入口。

### 安全

- 登录防爆破（用户 + IP 失败计数锁定，5 次 / 15 分钟）、PBKDF2 口令哈希、会话令牌哈希入库。
- 可选 TOTP 两步验证（兼容标准验证器），系统级总开关。
- 初始管理员未配置口令时生成随机口令并强制首次登录改密。
- 安全响应头与 CSP，仅可信代理才采信 X-Forwarded-For，OpenAPI 文档默认关闭。

### 模型接入

- 配置化多厂商接入（`config/models.yaml`），OpenAI 兼容协议，自动重试与降级。
- 当前配置：公司采购 OpenAI GPT（gpt-5.4 生成与图片理解、gpt-5.5 评审、gpt-5.4-mini 降级备用），Embedding 同用 OpenAI text-embedding-3-large，无内网模型依赖。DeepSeek / 智谱 / 百炼 / 私有化 Ollama、vLLM 只改配置即可接入，样例见 `config/models.example.yaml`。

## 部署与升级

- 全部业务数据入 MySQL（utf8mb4），表结构由应用首次启动自动创建，无需手工执行建表 SQL。
- 环境变量见 `.env.example`，至少配置 `TIANGONG_DB_URL`、`OPENAI_API_KEY`、`TIANGONG_ADMIN_PASSWORD`。
- 启动命令：`python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`。只支持单进程，不要加 `--workers`。
- 从旧版（任务制）升级：启动时自动把历史执行轮次迁移为计划、历史任务迁移为需求；「未指定项目」的遗留任务需管理员在项目管理中归属项目。正式迁移前用 `scripts/migrate_prod.sh` 全量备份。
- 验收材料：`docs/验收清单_V1.0.md`（迁移记录、25 条规则验收结果、全流程走查表与缺陷表）。

## 质量与验收

- 自动化测试 263 项全部通过，其中 `tests/test_acceptance_rules.py` 覆盖第 23 章 25 条核心规则。
- 试点项目全流程走查 24 步全部通过，走查中发现的缺陷已修复并补回归测试。
- 页面跳转专项巡检：修复打开失效任务无提示、侧栏入口不回列表、项目概览快捷入口状态不一致、跨项目进入任务后返回找不到等 8 项问题。

## 已知限制

- 单进程架构：用户、项目、任务为进程内内存态加数据库回写，不支持多实例部署。
- 图片理解与 Embedding 依赖内网 Ollama（`config/models.yaml` 中的地址），部署环境需能访问该服务，否则知识库入库检索与 PDF 图片理解不可用。
- 本地存量数据迁移后仍有 1 个「登录功能（PC+移动端）」遗留任务待确认归属项目。
- 自我学习体系（学习 Agent 离线异步优化）未纳入本版本，规则库目前为人工维护。
