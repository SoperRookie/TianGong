# 天工 v2.1.0 发布说明

- 版本：v2.1.0
- 发布日期：2026-10-14
- 标签：`v2.1.0`（dev 分支）
- 适用范围：内网部署，MySQL 8 + Python 3.12；升级步骤见 `docs/服务器部署文档.md`、`docs/Docker部署文档.md`

## 概述

v2.1 的主题是「需求理解的准确率」：把 AI 需求分析从一次性模型输出改成「分析 → 原文核验 → 独立复核 → 人工拍板 → 评测回归」的闭环，准确率变成可测量、可逐步逼近的数字，而不是靠感觉。

## 新增与变化

### 需求分析三道防线

- **引用溯源 + 程序核验**：每条分析要点带原文依据（quote），后端逐条核对 quote 是否真在原文里（全角 / 空格 / 标点差异不影响，PDF 断行按分段容错）。业务规则 / 边界条件 / 状态变化 / 权限要求四项没有依据或依据对不上的条目不进结果，自动降级为「必须确认」的待确认事项；其余项只打标。页面每条显示「✓ 原文依据」或「⚠ 依据与原文不符」。
- **独立复核 Agent**：第二个 Agent（可指定与分析不同的模型）对照原文逐条复核：理解错（数值 / 方向 / 条件写反，给出按原文改正的建议）、无依据、遗漏（补入前同样过原文核验，没通过的转待确认）。复核意见标在条目上不覆盖，由人「采纳改正 / 手动修改 / 删除 / 原条目没问题」；有质疑未处理时不能确认、不能沉淀。
- **分析更强的输入**：分析改用最高推理强度；注入项目画像与知识库中本项目（含同业务线、公共层）的历史需求与业务规则（排除该需求自己沉淀的文档，只用于理解术语与背景）；超长需求分片前先出全文大纲，跨章节引用不丢。

### 人工修改与采纳

- 分析页每条可改 / 删，每项可人工补充；待确认事项里「原文核验降级 / 复核补充」的条目确认成立可一键「采纳」回分析项。
- 修改留痕（`analysis_edits`）：进需求分析评测集的标准答案，也进学习规则语料（「需求分析人工修改 / 删除 / 新增」）；修改后已确认的版本变为旧版本，需重新确认才更新知识库。
- 带未处理复核质疑的条目不进测试设计上下文，也不进知识库。

### 需求分析评测（管理员，新页面）

- 评测集：需求详情「加入评测集」把人工过目 / 修改后的分析结果作为标准答案（同一需求重复加入即更新）；人工改过再确认时自动加入；评测页可逐项修订标准答案、备注、删除。
- 回归评测：选分析模型 / 复核模型，对评测集重跑完整流水线，裁判 Agent 与标准答案逐条语义对齐（逐字相同的由程序先行判定），统计 准确率 = 匹配 /（标准答案 + 捏造）、捏造率、理解错率、遗漏率，总计与按分析项；逐样本展开看理解错 / 捏造 / 遗漏明细；记录模型与三个 Prompt 的版本，后台串行执行。
- 新增 Prompt：「需求分析独立复核」「需求分析评测裁判」，Prompt 管理页可版本化调整；「需求分析（11 项）」内置默认已更新为带 quote 的结构。

### 需求编写规范

- 需求列表页「需求编写规范」：给产品 / 需求方的六条硬要求与文档模板（规则逐条编号、数值单位方向写死、状态流转成表、角色权限单独一节、异常分支明写结果、修订记录），可下载 Markdown 模板。

## 升级说明

- 存量需求的分析结果（纯文本条目）继续可用，页面显示为「未给出原文依据」；重新分析后即为新结构。
- 新增配置：`TIANGONG_ANALYSIS_REVIEW`（默认 true）、`TIANGONG_ANALYSIS_EVAL_AUTO_SAMPLE`（默认 true）。
- 建议上线后：挑 20~30 份已确认的典型需求逐条过目后「加入评测集」，跑一次回归评测记下基线；之后每次改 Prompt、换模型都跑一遍对比。
