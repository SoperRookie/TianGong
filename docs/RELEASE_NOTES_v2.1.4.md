# 天工 v2.1.4 发布说明

- 版本：v2.1.4
- 发布日期：2026-10-15
- 标签：`v2.1.4`（dev 分支）
- 性质：修复需求提取「源文件有、整理稿没有」的四层原因；无新增系统依赖，无表结构变更，升级步骤与 v2.1.0 相同

## 问题

生产上三条连赢活动需求（Axure 原型包 + 截图）的整理稿对照源材料逐行核查：剔除外观描述后仍有 12% ～ 17% 的需求句子没进整理稿，⚠ 条目里九成以上是模型改写原句时截掉了句尾条件。原因有四层，按影响从大到小：

| 原因 | 证据 | 本版处理 |
|---|---|---|
| 默认模型换成 gpt-5.6-sol 后提取量只有旗舰的三分之一 | 同样 21k 字输入：gpt-6-astra 输出 35k 字、gpt-6-sol 31k 字、gpt-5.6-sol 11k ～ 17k 字；没有截断，是模型把逐字摘录做成了摘要 | 新增 `TIANGONG_REQUIREMENT_EXTRACT_MODEL` 单独钉住提取模型；提取页模型下拉显示当前默认是哪个 |
| Prompt 要求「必须完整句子、字段 / 枚举 / 示例不单独成条」，逼着模型改写 | 原型里的需求大量是括号与列表，模型重组成句子时丢掉「无对应数据时显示 0」「点击后向下展开」这类句尾规则；带规则的示例被当样例数据剔除；图片理解结果被当界面清单修剪过重 | Prompt 改回逐字为先：材料是什么形式就按什么形式成条，字段清单 / 枚举值整行保留、带规则的示例保留、空数据与异常状态的显示规则保留；只剔除导航框架、脚本样式、纯样例数据和只讲颜色 / 位置 / 样式 / 可见性的行；只有文字完全相同才算重复，PC 与移动端各自保留 |
| zip 内中文文件名乱码，Axure 页面名与说明备注丢失 | 解析文本里页面标题是「页面：pc-µ┤╗σè¿Φ»ªµâàΘí╡…」（UTF-8 字节被按 cp437 解码），站点地图的页面 url 对不上包内文件，每页 `data.js` 的说明备注全部找不到：一条需求 6 个页面 0 条备注，另一条 12 页只有 1 条 | 压缩包解析对没有 UTF-8 标志位的 zip 条目按原字节依次试 utf-8、gb18030 还原，并按真实名落盘；Axure 页面名与说明备注随之恢复 |
| 分片切在图片理解结果中间，后面的片不知道属于哪个文件哪个页面 | 7 万字材料切 4 片，第 2、3 片开头是「### 极速百家乐U01」「### 顶部玩法项」，来源只能写「需求材料 › …」 | 每片带上开头所处的标题路径「文件 › 页面 › 章节」 |

另：自动提取的模型调用日志没带需求与项目归属，AI 中心按需求筛不到；现已补上。

## 升级后

- 之前用 gpt-5.6-sol 自动提取的整理稿偏薄：需求详情「需求提取」页点「重新提取」（选 gpt-6-astra 或 gpt-6-sol），再重新 AI 分析。
- 默认模型已改成低档型号的，`.env` 加 `TIANGONG_REQUIREMENT_EXTRACT_MODEL=gpt-6-astra`。
- 压缩包 / Axure 包内中文文件名乱码的存量需求（解析文本里页面名形如「µ┤╗σè¿」）：附件列表点「重新解析」，页面名与说明备注补回来；解析完整理稿标过期，分析时自动重提。

## 验证

- 单元 / 接口测试 +4：无 UTF-8 标志位的 zip（UTF-8 与 GBK 两种）还原后 Axure 页面名与说明备注不丢；分片标题路径；提取模型配置优先级（页面选择 > 配置 > 默认）；自动提取调用日志带需求归属。
- 真实模型回归（用三条生产需求的材料以 gpt-6-astra 重跑新版提取、对比未覆盖行数）**本次没有跑成**：OpenAI 账户额度耗尽（429 insufficient_quota，astra → sol → luna 全链失败）。充值后用 `scripts` 外的验证脚本重跑即可，对比口径在《业务流程与节点逻辑》1.5 节。
