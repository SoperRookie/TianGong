# 天工 v2.1.2 发布说明

- 版本：v2.1.2
- 发布日期：2026-10-14
- 标签：`v2.1.2`（dev 分支）
- 性质：把《业务流程与节点逻辑》梳理出的 13 条实现缺口全部补齐；升级步骤与 v2.1.0 相同

## 需求分析闭环

- 评测裁判支持跨分析项匹配：编号对可带 AI 输出所在分析项（`[g, p, "boundaries"]`），归类不同的同一事实算匹配，不再同时记一次遗漏和一次捏造。
- 评测的 AI 输出与标准答案同口径：复核判无依据的条目去掉、判理解错且给了改正的取改正文本后再计分，样本记录 `review_applied`。
- 分析时的知识注入排除范围扩大到本需求发起的任务沉淀的测试点 / 用例 / 终稿（`origin_ref` 为任务 id）。
- 采纳降级事项回分析项时保留原文依据并重新核验；「原条目没问题」留痕记录驳回了什么复核意见，但不算内容修改、不会让已确认版本过期。
- 附件在分析之后有追加 / 重新解析 / 删除时，分析页提示「当前结果基于旧输入，建议重新分析」（`analysis_meta.inputs` 指纹）。

## 解析

- 解析结果体检：文本几乎全是代码 / 样式 / 乱码（中文占比 < 5% 且代码类行 ≥ 30%，或乱码串 ≥ 5 处）时附件标「疑似非需求文本」，AI 分析与发起设计先拦截，页面确认后可继续。之前这种内容会直接消耗几百次模型调用。
- 扫描版 PDF 不再直接报错：没有文本层的页按 150 dpi 整页栅格化送图片理解（大图自动切块）；整份无文本层且超过 60 页才拒绝。
- Word 表格单元格里的图片按位置提取（Axure 的 Word 规格导出常把页面截图放在表格里），合并单元格按关系 id 去重。
- PPT 里的 emf / wmf / svg 经 LibreOffice 栅格化后送图片理解，没装则跳过。
- Axure 导出包里页面 `images/` 下短边 ≥ 400px 且 ≥ 20KB 的位图当作整幅设计稿 / 截图送图片理解（全包最多 30 张），按钮图标等切图碎片和 svg 切片仍跳过。

## 任务与执行

- 测试设计任务并发上限 `TIANGONG_TASK_MAX_CONCURRENCY`（默认 2），超出的保持排队，排队中也可取消。
- 分片直接生成模式支持断点续跑：检查点按片隔离（拆解结果存 `chunks[片号]`，模块结果键名加片号前缀），失败后重试不再整体重跑。
- 测试计划：结束轮次时本轮把计划内用例全部执行过则计划置「已完成」；已完成的计划再开一轮退回「进行中」。
