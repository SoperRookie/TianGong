# 天工 v2.2.0 发布说明

- 版本：v2.2.0
- 发布日期：2026-10-30
- 标签：`v2.2.0`（dev 分支）
- 性质：引入「端」（H5 / 游戏后台管理 / 商户后台）作为需求提取、测试点审核、用例生成与导出的第二个维度；拆解前新增「端到端场景」一步。无新增系统依赖，无表结构变更，升级步骤与 v2.1.0 相同

## 为什么

一份活动需求通常同时写了三个端：商户后台配置活动与查看报表、H5 用户参与、游戏后台管理派奖与结算。之前整理稿、测试点、用例都是一张平铺的列表，审核时三个端的测试点混在一起；移动端的测试点先审完也只能等全部审完再一起生成；导出也是整份，拿不出「只给商户后台的那份」。用户要求：提取完成后按端汇总看总需求；测试点按端分列表，哪个端审完了哪个端单独生成、单独评审；导出按端分开，脑图和表格都要；测试点生成要参考端到端的场景。

## 端的定义与判定（新 `app/terminals.py`）

- 端清单：三个业务端 H5（`h5`）、游戏后台管理（`game_admin`）、商户后台（`merchant_admin`），加固定的「通用」（需求说明 / 版本记录等）、「端到端」（跨端场景点）、「其他」（判不出来的）。业务端的 key / 名称 / 关键词可用 `config/terminals.yaml` 覆盖，文件不存在或写坏了用内置。
- 判定三层，前一层判到了后一层不再动：

| 层 | 时机 | 做法 |
|---|---|---|
| 模型归端 | 需求提取完成后 | Prompt `terminal_classify`（`reasoning_effort=low`，一次调用）：送整理稿每个顶层章节（有文件夹分组的按文件夹，否则按页面）的页面名、区块名与前 6 条条目原文，模型按「谁在用、从哪进」判端；只认输入里的章节键与端清单里的 key。结果存 `extraction.terminals{章节: 端}` 与 `terminal_reasons`。开关 `TIANGONG_REQUIREMENT_EXTRACT_TERMINALS`（默认开），关掉只按关键词判 |
| 章节对回 | 发起测试设计 | 模块名就是「文件夹-页面-区块」：去掉多需求合并时的「需求标题-」前缀后，按整理稿章节键取最长前缀匹配（「活动运营后台-活动列表-基本配置」对「活动运营后台」）。章节的端随提取时的判定与人工改动一起带进任务（`analysis.terminal_rules`） |
| 关键词兜底 | 以上都对不上 | 名字按关键词判：商户后台 › 游戏后台 › H5 › 通用（「商户管理后台」含「管理后台」、「游戏后台-大厅配置」含「大厅」，所以后台类先判）；英文关键词按整词匹配；都兜不住记「其他」 |

- 端到端场景点固定「端到端」；人工新增 / 修改测试点可直接指定端。

## 1. 提取完成后的三端汇总

需求提取页顶部新增可折叠的「三端汇总 · 总需求 N 条」：总计章节 / 页面 / 区块 / 条目数，每个端一行列出页面数、区块数、条目数与所属章节清单（条目按行类型算：表格 / 流程行按行数、示例图按说明加文案条数、其余一行一条）。每个章节右侧有端的下拉，改了调 `POST /api/v1/requirements/{id}/extraction/terminals`（`requirement.edit`，`{section, terminal}`；没有逐条结构 409、端不合法或填「端到端」400、章节不存在 404），记 `extraction.terminal_edits`；之后发起的测试设计按新归属走，已经拆完的任务不变。接口 `extraction` 视图新增 `section_terminals`、`terminal_summary`、`terminal_options`。

## 2. 测试点按端分列表，拆解参考端到端场景

- 测试点字段新增 `terminal`（端）与 `scenario`（端到端场景名），`normalize_points` 保留、`generation_view` 带给生成。任务详情 `GET /tasks/{id}` 返回 `terminals`（端清单）、`point_terminals`（按端的总数 / 待审核 / 已通过 / 已驳回 / 已生成 / 已通过未生成）、`case_terminals`（每条用例的端）；打开旧任务时给没有端的测试点补上并落库。
- 测试点页新增端页签「全部端 / H5 / 游戏后台管理 / 商户后台 / 端到端」，各自计数、待审核角标；列表、模块筛选、脑图都按当前端过滤；模块标签下方标端；人工新增测试点预填当前模块与端；修改弹窗可改所属端（`modify` 的 `terminal` 不合法报错）。
- **端到端场景**（Prompt `e2e_scenarios`，`reasoning_effort=high`，开关 `TIANGONG_POINT_E2E` 默认开）：拆解分片之前通读全文（超过 120000 字按各章节开头拼接）一次调用，带上各章节所属的端，梳理 3 ～ 10 条跨端业务主线（如「商户后台配置 → H5 参与 → 游戏后台结算 → 商户报表」），每条带环节链与 ≤ 8 条跨端一致性测试点（后台配置在前台何时生效、前台产生的数据在后台与报表里的口径、一端撤销后另一端的状态）。程序兜底：`terminals` 只认端清单里的 key 且至少 2 个不同的端（单端不是端到端），没有测试点的场景跳过。两个去处：（1）主线清单注入每片拆解 Prompt 作参考（「端到端场景参考」块），要求本片原文写到的跨端一致性规则拆成测试点、原文没写的不补；（2）场景点以模块「端到端-<场景名>」、`source=e2e`、`terminal=e2e`、`basis` 为主线说明追加进拆解结果，与明文点一起待审核。这一步失败只丢场景、拆解照常，trace 记「端到端场景」一步。测试点页「端到端」页签下每条带「主线「…」」依据，来源列标「端到端场景」。
- 测试默认关（`tests/conftest.py` 两个开关都 false），避免每个 API 测试多消耗桩回复。

## 3. 按端单独生成、单独评审

- `POST /tasks/{id}/confirm` 新增 `terminal`：只取该端已通过（没审过取非驳回）的测试点进生成；端不合法 400，该端没有可生成的点 400，已完成任务该端没有新通过未生成的点 409。`context.confirm_terminal` 记下这次确认的端，失败续跑（`retry` 确认后续跑那一支）仍只跑这个端，生成结束清掉。
- 页面：等待确认时切到某个端，底部按钮变成「只生成『X』用例」并保留「全部端一起生成」；任务完成后，每个有新通过未生成测试点的端各出一个「生成『X』用例（N 条）」按钮，加「全部新通过的一起生成」，走已有的增量生成并入（`resume_stage=incremental`，取消 / 失败回已完成）。
- 用例审核页同样按端分页签并计数；用例的端按来源测试点的多数端 › 所属模块的端 › 模块名关键词 › 其他（`case_terminals`）。通过 / 驳回 / 修改等评审动作不变。

## 4. 按端导出

- 测试点 `GET /tasks/{id}/points/export?fmt=xlsx|xmind&scope=all|approved&terminal=` 与用例 `GET /tasks/{id}/download/{fmt}?terminal=`（xlsx / csv / xmind，`scope=approved` 同样生效）都支持按端过滤；端不合法 400，该端没有测试点 / 用例 404；文件名带端名（「测试点-商户后台.xlsx」「测试用例-H5.xmind」「正式用例-游戏后台管理.xlsx」）。
- 测试点 xlsx 在「模块」后新增「端」列，来源列新增「端到端场景」；xmind 模块节点标签带端名。
- 页面：测试点页与用例页的导出按钮随当前端页签带 `terminal=`；概览页新增「按端单独导出」一排（每个端 xlsx / csv / xmind）。

## 升级后

- 无新增依赖、无表结构变更。已有任务打开时测试点自动按模块名关键词补端（没有提取时的章节归端），分到「其他」的在修改弹窗里改端即可；想要端到端场景点的任务在测试点页重新拆解。
- 已有需求的整理稿没有章节归端记录，提取页三端汇总按章节名关键词显示，可直接在每章右侧改；重新提取时模型再判一次。
- 两个开关默认开：不想在拆解前多一次全文调用加 `TIANGONG_POINT_E2E=false`；不想在提取后多一次归端调用加 `TIANGONG_REQUIREMENT_EXTRACT_TERMINALS=false`。
- 端的关键词不合业务叫法时在 `config/terminals.yaml` 写 `terminals: [{key, label, keywords}]` 覆盖，改完重启。

## 验证

- 单元 / 接口测试 +7（498 通过）：名字关键词判端（商户 / 游戏后台 / H5 / 通用 / 对不上）、模块名按章节对回与「需求标题-」前缀、用例按来源测试点归端；三端汇总计数（表格 / 流程 / 示例图按行算）；三端拆解流程（三个端各自确认生成、不存在的端 400、没通过点的端 400 / 409、第二个端走增量并入且第一个端的用例不动、按端导出 xlsx / xmind 文件名带端名、修改测试点的端）；端到端场景（注入块进了每片拆解、场景点以 `e2e` 模块与来源落下、摘要与 trace、按「端到端」确认生成）；端到端调用失败只丢场景拆解照常；章节归端只认输入里的章节键与合法端；提取三端汇总接口、人工改端（409 / 400 / 404）与改后发起设计模块按新归属落端。
- 页面在隔离环境（SQLite、桩模型）实际打开核过：提取页三端汇总表与下拉，测试点页端页签与计数、端到端列表的主线依据、按端导出按钮、按端生成按钮；用例页端页签；无控制台报错。
